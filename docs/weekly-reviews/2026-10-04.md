## 4. 本週實際改動與驗收

### 主項:`references/security-and-privacy.md` 新增「Source transcript permissions」一節

- **動機**:方向 C 的發現——openai/codex#21660 讓 rollout 檔在共用主機上 world-readable;本 Skill 輸出側已全面 0600/0700,但文件從未告知操作者「輸入來源在上游就已暴露」。對一個以 local-first、隱私優先自我定位的 Skill,這是必須誠實揭露的邊界。
- **做法**:在 Data boundaries 與 De-identification boundary 之間新增一節,內容:(a) 說明腳本輸出 owner-only 但來源檔不受我們控制;(b) 指出 Codex rollout 0644 的上游議題與影響;(c) 共用主機上開工前的三步驟——`chmod 700 "$CODEX_HOME"`、`chmod -R go-rwx "$CODEX_HOME/sessions"`、匯出檔與暫存副本同樣 owner-only、每次升級後複查;(d) 明示這是輸出側規則的補充而非替代,且 Skill 不得暗示已關閉早於執行前的暴露窗口。
- **原則檢查**:純文件,不改任何行為;強化而非削弱隱私立場;與既有「owner-only mapping parent」「報告刪除邊界」的誠實揭露風格一致。

### 次項:`SECURITY.md` Operator responsibility 補一句來源側權限提醒

- 與主項同根:操作者責任段原本只要求輸出放私有目錄,現補上共用主機須先驗證來源 transcript 權限、附 #21660 連結與 `chmod 700 ~/.codex` 範例、並說明輸出側 owner-only 無法回溯修復執行前的暴露。
