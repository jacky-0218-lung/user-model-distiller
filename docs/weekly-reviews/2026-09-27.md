  - 來源:https://www.havoptic.com/tools/openai-codex 、https://learn.chatgpt.com/docs/changelog

### 方向 B — 競品與類似工具(memory / personalization)

- **supermemoryai/supermemory#1348(open feature request)**:使用者向主流 hosted memory 工具要求「memory governance layer」——PII 遮蔽、retrieval 前的 poisoning 篩查、稽核紀錄——並明言該專案目前「retrieval 與 LLM 之間沒有任何治理層」。討論中的 disposition envelope 構想(typed admission states、provenance hash、稽核紀錄)本 repo 已以 status 狀態機 + digest-bound receipt + 私有 run 層實作。**市場正在向本 repo 的既有定位靠攏,是差異化持續有效的直接證據;無結構性新點子需要借鏡。**
  - 來源:https://github.com/supermemoryai/supermemory/issues/1348
- mem0 官方發布 memory security best practices blog,主打加密與存取控制,仍屬 hosted 模式的補救框架,與 local-first + 人工核准路線互補而非競爭。
  - 來源:https://mem0.ai/blog/ai-memory-security-best-practices

### 方向 C — 安全與隱私強化

- **arXiv 2604.16548《A Survey on the Security of Long-Term Memory in LLM Agents: Toward Mnemonic Sovereignty》(本週主要行動依據)**:提出六階段記憶生命週期(write / store & manage / retrieve / execute / share & propagate / forget & rollback)與九個治理原語,並指出「沒有任何已發表架構九項全備」、store/share/forget 階段研究最少。逐項對照本 repo:write/retrieve/execute 全覆蓋,share 依設計不適用;**store 與 forget 階段有一個誠實的缺口——profile 有紀錄層級的歷史與 supersession,但沒有檔案層級的快照/一鍵回滾**,誤核准後的復原目前靠 supersede/forget + 使用者自備備份。本週把這個對照直接寫進 `docs/threat-model.md`(見第 4 節),快照功能列入佇列(落在 `profile_tool.py`,須等 stacked 合併)。
  - 來源:https://arxiv.org/abs/2604.16548
- openai/codex#24948(rollout 大檔問題,上週主項的依據)**仍 open**,上游未修;#33 的串流解析與補救指引維持必要。
  - 來源:https://github.com/openai/codex/issues/24948

## 4. 本週實際改動與驗收

### 主項:CI 增加 Python 版本矩陣(`.github/workflows/ci.yml`)

- **動機**:方向 D 的發現——宣告支援 `>=3.10` 但只測單一版本,版本特定的回歸(語法、stdlib 行為差異)完全測不到。
- **做法**:test job 增加 `strategy.matrix.python-version: ["3.10", "3.12", "3.14"]`(最舊支援版 / 中間版 / 最新穩定線),`fail-fast: false` 讓各版本獨立回報;新增 `actions/setup-python` step,依 repo 供應鏈慣例**釘完整 commit SHA**(`5fda3b9…`,對應 v7.0.0,dependabot 既有設定會接手後續更新)。其餘步驟不變。
