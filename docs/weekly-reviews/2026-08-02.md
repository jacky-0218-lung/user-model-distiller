### 方向 C — 安全與隱私強化（**本週改動來源**）

- 公開威脅規則庫 Agent-Threat-Rules 的 **ATR-2026-00312**「Unicode variant selector ASCII smuggling」：攻擊把每個 ASCII 字元藏為 `U+E0100 + ord(ch)`（可列印 ASCII 落在 U+E0120–U+E017E），多數渲染器完全不顯示，LLM tokenizer 卻能解碼——在視覺全空白的字串裡夾帶越獄指令。規則同時指出：**正當的 IVS 用法最多在一個 CJK 基字後放一個 selector，絕不會出現連續 selector run**；標準 variation selector（U+FE00–FE0F）有 CJK／emoji 的正當用途。此規則直接佐證上週佇列的「擴大隱形字元類別」項目，並提供了避免誤傷 emoji 的設計依據（區分 supplement 區塊與標準區塊、以 run 為警訊）。此即本週改動。
  - 來源：https://github.com/Agent-Threat-Rule/agent-threat-rules/blob/main/rules/prompt-injection/ATR-2026-00312-unicode-variant-selector-ascii-smuggling.yaml
- Repello《Emoji Prompt Injection》與 DEV Community 的 Unicode sanitizer 實作文章：均證實 variation selector 夾帶（含 U+FE00–FE0F 每字 4 位元的低頻寬通道）已是實務上被利用、且 guardrail 普遍看不見的攻擊面。

## 4. 本週實際改動與驗收

### 改動:variation selector 納入隱形字元防禦(四層一致)

依 ATR-2026-00312 的設計依據,把兩個區塊分開處理:

- **variation selector supplement(U+E0100–U+E01EF)→ 直接納入拒絕類別。** 這是 ASCII smuggling 的主通道(240 個碼位,足以映射整個位元組空間的大部分);剝除它只影響字形選擇、不影響文字內容,誤傷風險趨近於零。四層同步:
  1. `normalize_sessions.py`:`DECEPTIVE_INVISIBLE_PATTERN` 加入該區塊,剝除並計入 `redaction_count`;
  2. `privacy_guard.py`:`DECEPTIVE_INVISIBLE_RE` 同步——已正規化檔案含此字元即為篡改,blocker;
  3. `tools/check_repository.py`:repo 追蹤檔案守門同步;
  4. `tools/skill_bundle.py`:bundle 檔名與內容掃描同步(receipt schema 維持 1.1,類別擴大已記入 CHANGELOG)。
- **標準 variation selector(U+FE00–U+FE0F)→ 保留 + run 警訊。** emoji(U+FE0F 極常見)與 CJK 相容序列需要它,納入拒絕類別會誤傷幾乎所有含 emoji 的 transcript。但正當用法絕不會連續出現,且每個 selector 可攜帶 4 位元資料,故 `privacy_guard.py` 新增 warning **`variation_selector_run`**(連續 ≥2 個觸發),比照 `zero_width_joiner`:local 模式警告、`external-review` 模式升級為阻擋。此處理方式與既有 U+200C/U+200D 的先例完全一致。

文件同步(避免文件與程式碼不一致):`install.md` 拒絕類別清單加入 supplement 區塊並註明標準 selector 仍放行、`security-and-privacy.md` 剝除清單與保留理由各加一條、`CHANGELOG.md` 0.3.0(未發版)行為變更加一條並修正「已知限制」中「variation selector 不在其中」的舊敘述。

**未改動**:核心原則、`profile.json` schema、approval/digest 流程、receipt schema 版本、release workflow 一律未動。U+200C/U+200D 維持保留。

### 新增測試(基準線 117 → 120)

1. `test_variation_selector_supplement_is_removed_but_emoji_selector_stays`(normalizer):以 ATR 的實際編碼(`chr(0xE0100 + ord(c))`)驗證 smuggled 字串被剝除且計數正確,同一句中的 emoji `U+2702 U+FE0F` 完整保留。
2. `test_variation_selector_supplement_blocks`(privacy gate):同一編碼出現在「已正規化」檔案 → `deceptive_invisible_characters` blocker。
3. `test_variation_selector_runs_warn_but_single_emoji_selector_passes`(privacy gate):單一 emoji selector 完全不觸發警告(pass);`U+FE00 U+FE0F` 連續兩個 → local 警告、external-review 阻擋。
4. 既有的四層 pattern 一致性測試(`test_guard_pattern_matches_the_normalizer_pattern`)自動涵蓋新區塊——四層任何一層漏改都會失敗。
