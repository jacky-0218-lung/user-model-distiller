## 4. 本週實際改動與驗收

### 主項:佇列 2+3 合併評估 → 決議「維持現狀」,理由固化進正式文件

**`--as-of` 歷史重建:不做。** 三個理由:(1) **系統性不完整卻看似完整**——`forget` 依核心保證不留痕跡、`set-status superseded` 沒有可定年的替代核准,任何自動「時點重建」都必然默默漏掉這兩類事件,產出一份看起來完整的假稽核視圖;Zylos 的治理原則(來源可見性必須誠實)反向適用:偽稽核比沒有稽核更糟。(2) **資料面要補齊就得改 schema**(狀態變更時間戳),介面變更換一個中價值功能,不划算;且 `profile-schema.md` 已明文「刻意不設 `superseded_at`」(同一事件兩個時間戳可能互相矛盾)。(3) 已有替代:文件的 supersession-chain 手動重建程序公開承擔同樣的 caveat,加上 #18 留下的契約測試把「`--as-of` 只管到期」鎖死,行為不會悄悄漂移。

**append-only 稽核紀錄:現階段不做。** 核心衝突:**不可變歷史與可移除記憶只能選一個**。即使是「無內容」的稽核條目(只記 ID 與 digest),描述性 ID(如 `prefers-typed-python`)本身就洩漏被 forget 的內容;而一份為了尊重移除而必須可改寫的紀錄,就不再是 append-only。本 repo 選可移除記憶;profile.json 本身(evidence refs＋digest＋approved_at)已是每筆活躍規則的完整稽核記錄;要防竄改的使用者可自行把檔案放進自己的版本控制——那份歷史屬於使用者,可自留可銷毀,這正是 local-first 的本意。**重啟條件**:(a) 出現跨機同步或爭議仲裁需求;(b) schema 2.0 本來就要動時一併評估。

決策理由**固化進 `references/profile-schema.md`**(「What `--as-of` does and does not do」擴寫＋新增「Why there is no separate audit log」一節),不是只留在本報告——未來讀者在 schema 文件現場就能看到「這是刻意設計」而非「還沒做」。

### 配套小改動(方向 D 的兩個可用性修正)

- `SKILL.md` 第 8 節:主要編譯範例**移除**寫死的 `--as-of 2026-07-20T00:00:00Z`(過去時間戳的複製貼上陷阱,見方向 D);補一段說明 `--as-of` 僅供預覽到期邊界、不重建歷史、傳過去時間會把已到期規則編回視圖。
- `profile_tool.py`:`compile --as-of` 補 CLI help 文字(與文件同語意)。**無任何行為變更**。
- `CHANGELOG.md` 0.3.0「變更」補一條完整記錄。
